# Milestone 10: MongoDB Connection Profile and No Replay

Date: 2026-09-27. Status: **blocked; SCRAM/TLS is not enabled or qualified**.
This is a bounded handoff, not a milestone pass.

Historical record: the subsequent [M10 remediation](milestone-10-remediation.md)
repairs the adapter layering. This document preserves the original failed stage;
the original fixture-only evidence did not qualify production TLS/SCRAM.

## Starting point and scope

- Started on clean local `main` at `8ebbe134a60834023ede79f1ed68ca0cb3645b9b`.
- Kept Go 1.27.0, mongo-driver v2.9.1, and MongoDB 8.0.32; no dependency upgrade,
  driver fork, Weir identity/authentication subsystem, or Search change.
- Preserved the existing one-host, explicit-port, credential-free MongoDB URI
  profile. `ValidateURI` now bounds the URI at 4096 bytes, limits the authority to
  one host and port, allowlists URI options, rejects duplicate/case-colliding
  options and unsupported auth/TLS settings, and runs in static config validation
  before DNS, CA-file access, or driver setup.
- Structurally valid explicit SCRAM-SHA-256/TLS URIs are rejected by `ValidateURI`
  with a sanitized `not qualified` error. The application does not read their CA
  path or open a socket. Native/BackendExpression replay guards remain unchanged.

## Blocking evidence

The existing Mongo reply guard cannot currently coexist with the driver's standard
TLS setup. In mongo-driver v2.9.1,
`x/mongo/driver/topology/connection.go:264` calls the configured `DialContext`, then
`connection.go:272` wraps the returned connection with TLS. Weir's
`internal/mongostore/wire.go:41` reads the first 16 bytes returned by that dialer as
an unencrypted Mongo wire header. A real owned TLS/SCRAM MongoDB 8.0.32 fixture
connected through the production adapter reached `topology.ServerSelectionError`;
the failure is consistent with the guard interpreting TLS records as Mongo frames.
The relevant failed fixture log is retained at
`.testdata/mongo-m10-11034-1/mongod.log`.

Do not remove `boundedConn`, set `InsecureSkipVerify`, move TLS termination outside
the backend, or treat `retryWrites=false` as replay proof. The safe next step is a
separately reviewed, bounded TLS-aware reply inspection design that preserves
standard driver certificate validation and cancellation/handshake limits. Until
that exists, authenticated and TLS MongoDB URIs remain rejected.

The pinned driver passes the URI mechanism from
`x/mongo/driver/topology/topology_options.go:147` to `auth.CreateAuthenticator`;
`x/mongo/driver/auth/auth.go:33` registers the explicit SCRAM-SHA-256 factory.
The URI parser requires that explicit mechanism because
`x/mongo/driver/auth/default.go:54` can fall back to SCRAM-SHA-1 during implicit
negotiation. The 391 branch in `x/mongo/driver/operation.go:962` continues only
after `Authenticator.Reauth` succeeds. The explicit SCRAM authenticator's
`x/mongo/driver/auth/scram.go:96` returns an unsupported-reauthentication error.
This source inspection is not acceptance evidence for the running Weir adapter;
no authenticated Weir mutation, 391 failpoint, successful-write reply loss, or
reconnect/replay test passed this stage.

## Owned fixture evidence

`internal/testmongo/secure.go` creates a separately marked `.testdata/mongo-m10-*`
fixture using the pinned MongoDB 8.0.32 binary, a fresh loopback port, a one-member
replica set, required TLS, and SCRAM users. Test-only private keys and passwords
are generated by the fixture and are never printed. The application user has only
`find`, `insert`, `update`, and `remove` on `records`, plus `listCollections` on
its database; the fixture exercises hello/buildInfo metadata, CRUD, bad password,
missing password, untrusted CA, wrong hostname, and insufficient privileges using
the standard driver. This proves the fixture's MongoDB TLS/SCRAM behavior, not
Weir's authenticated connection path.

The test fixture uses at most one mongod process, one ephemeral loopback listener,
a four-connection test client pool, 2-second connect/selection bounds, a 15-second
fixture connection wait, a unique owner-marked directory, and 24-hour test-only
certificates. It does not use Docker or alter host DNS, trust stores, or network
settings. Failure cleanup stops the owned process, removes generated keys and data,
and retains logs; successful cleanup removes the owned fixture directory.

## Tests and failures

Passed during this stage:

- `GOPROXY=off GOSUMDB=off go test -count=1 ./...`
- `GOPROXY=off GOSUMDB=off go test -race -count=1 ./...`
- `GOPROXY=off GOSUMDB=off go vet ./...`
- `GOPROXY=off GOSUMDB=off go vet -tags integration ./...`
- `WEIR_M10_INTEGRATION=1 go test -tags integration ./internal/testmongo -run '^TestSecureMongoFixture$' -count=1 -v`
- `WEIR_M10_INTEGRATION=1 go test -tags integration ./internal/mongostore -run '^TestMongoSCRAMTLSProfileFailsClosedAtBoundedReader$' -count=1 -v`

Fixture bring-up exposed and fixed a PEM key-format error, localhost-only bootstrap
ordering, an invalid role action, and a mismatch between the fixture user's
`authSource` and creation database. Those failed runs retain only owner-marked logs
under `.testdata/mongo-m10-*`; generated key files and data were removed. A separate
adapter attempt failed with `topology.ServerSelectionError` at the TLS/wire-reader
boundary above. No credential, private-key content, or raw authenticated URI was
written to test output.

Not passed or not run: Weir Read/CRUD/Bulk/Scan/Native/BackendExpression over
SCRAM/TLS; 391 and post-success reply-drop command-count evidence; TLS handshake
stall and authenticated cancellation/drain/race loops; expired-certificate test;
legacy unauthenticated Mongo integration suite. The full default repository test
and race suites, plus default and integration-tagged vet, passed; the legacy live
Mongo suite was not run because its owner-marked local fixture was not active.
These are outstanding qualification gates, not waived requirements.
