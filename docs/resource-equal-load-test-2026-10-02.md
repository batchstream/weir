# Weir 与直连：相同实际数据库 CPU 的吞吐测试

2026-10-02。本轮使用冻结的 v4 Weir 与同一负载客户端，补测实际数据库 CPU 相近时的成功吞吐。混合读写中，MongoDB 有两组合格对照，成功吞吐增加 93.9%；ES 只有一组合格，观测为 17.23 倍。MongoDB 纯写有三组健康的实际 CPU 相近观测，吞吐增加 28.1%–42.6%，但没有建立固定 0.10 核的合格重复。ES 纯写两组观测到 Weir 的 CPU 更低、吞吐更高，但三组没有同时满足 CPU 匹配和健康门槛。本轮没有完成任何工作负载在预设固定 0.10 核目标内的三组合格重复，不能把上述观测当作稳定的最大容量提升。

有界负载试验全部结束。MongoDB 纯写最后一轮直连六次校准未锁定目标；Weir 该轮一次校准为 450 次/秒、0.099309 核，随后正常跳过正式补测并清理，未扩大预算。

两组健康观测均为 16.56 倍吞吐，且 Weir 路径的实际 DB CPU 更低；这是批量路径有效的观测证据。它们属于次要描述性结果，不按 CPU 比例折算，也不能声明已经验证了稳定的 16.56 倍容量。全部六个纯写正式试验的 API 错误、UNKNOWN、OOM 均为零，warm+measure 共 378999 个 APPLIED 写入完成逐条内容审计。冷启动和校准阶段的错误另列，不能据此宣称整轮没有错误。

新 ES 纯写 cohort 的直连共同冷启动预热有 10390 个 API 错误，其中 7513 个 UNKNOWN；审计发现这批 UNKNOWN 中 4031 个实际落库。Weir 的共同预热完成 800 次/秒，但有调度延迟。二者都不计正式结果，原始账本与审计保留。正式 CPU 运行点是在后续有界校准后选定，不能把预热期间的故障隐藏为“全轮零错误”。

## 资源和延迟成本

这里的内存是测量窗口内进程 RSS 峰值，配对汇总取中位数；不是内存配额或容器历史内存峰值。

|范围|DB RSS：直连 / Weir（MiB）|Weir 实际 CPU（核）/ RSS（MiB）|成功操作 p95：直连 / Weir（ms）|
|---|---|---|---|
|MongoDB 混合，两组合格|320.5 / 325.8|0.553 / 26.3|2.4 / 16.0|
|MongoDB 纯写，round0 两组 CPU 相近的次要观测|420.6–423.3 / 417.0–423.3|0.251–0.260 / 25.2–25.3|3.9 / 11.0|
|ES 混合，一组合格|912.8 / 925.7|0.489 / 28.9|8.4 / 9.0|
|ES 纯写，两组健康次要观测|918.8–922.3 / 1003.8–1009.0|0.395–0.406 / 27.3–27.4|8.1–8.2 / 8.9|

Weir 可以独立分配资源；本轮已给 4 核 CPU。上述数据库 CPU 效率改善需要额外约 0.25–0.56 核 Weir CPU，整体 CPU 并未下降。MongoDB 混合收集窗口也把 p95 从约 2.4 ms 提高到 16 ms。ES 纯写的数据库 RSS 上升约 85 MiB，所以 CPU 相近不代表内存和 IO 压力相同。

本轮测量一个 Weir 实例，未实测 HPA 横向扩容；不能把单实例结果线性外推为多副本吞吐或数据库保护能力。

ES 纯写丢弃超标的 r022 中，数据库容器测量期内存最高约 1427.6 MiB，容器生命周期峰值曾达 1536 MiB 上限，OOM 计数增量为零。生命周期峰值不等于本格持续占用，也不足以单独解释丢弃原因；不能只看进程 RSS 便认为数据库没有内存压力。

## 测试方法和边界

数据库配额均为 0.25 核、1536 MiB，目标总进程 CPU 为 0.10 核；每条路径必须在目标的 ±5% 内，同一配对两侧 CPU 的相对均值差还必须不超过 5%。吞吐按完整 60 秒测量窗口的成功操作数计算，CPU 按该窗口内全部采样计数的实际首末时间跨度计算。每个工作负载计划三组交替配对 D/W、W/D、D/W，正式试验前另有 20 秒预热。校准、共同预热、失败和补测分别保留。

Weir 可用 4 核、4608 MiB；客户端可用 2 核、2048 MiB，64 个客户端并发/Weir session，单个 Weir 进程。直连连接池为 4；Weir 后端并发/连接池为 2，最大批量 32，普通读上限 16 KiB，MongoDB 混合负载收集窗口 10 ms，其余 5 ms。这是两条已选部署路径的比较，连接池大小也是路径差异的一部分。

负载为约 1 KiB 文档的 90% 读/10% 写，以及纯写。每格仅重建独立测试集合或索引并播种相同的 1000 个读取键；写入不自动重试，完整 warm+measure 的 APPLIED 结果逐条审计。同一数据库的各格保持同一进程、存储与实际配额。MongoDB 使用独立 EKS fixture 和普通 emptyDir；ES 整轮使用独立 Docker fixture 和普通磁盘 volume。本轮 ES 不与以前的 tmpfs 结果合并。

MongoDB 两条路径使用相同的单成员 replica set、directConnection URI 和 majority 写确认。直连等待单操作写确认，Weir 等待数据库批量命令及结果游标完成验证后发布 APPLIED；只有 API 成功且 APPLIED 才计成功操作。没有把 accepted 入队计作成功。此确认语义检查来自冻结代码和实际配置，不是网络抓包，也不代表多成员集群的复制成本。

CPU 匹配与运行健康分别判断。正式健康门槛包含 API/UNKNOWN/OOM 为零、测量丢弃不超过 0.1%、无持续丢弃或客户端/Weir 瓶颈。每个工作负载最多两轮重新校准，必要时完整重做失配的配对；失败试验原样保留。ES 初始混合校准未达目标，使用这两轮中的第一轮继续，正式替换只剩第二轮预算。

ES 对“诊断采样造成固定 CPU 底值”的排查：同一 Java 进程无业务、原诊断采样运行约 30 秒时，进程 CPU 为 0.01718 核；仅 proc 采样空闲约 0.01655 核。该证据不支持这项猜测，因此保持原采样方式，不扣空闲基线。安全移交测试协调进程时保持同一 Java PID/start ticks、容器、volume 和配额，只有一个协调进程负责清理。中断校准 r008 单列，未声明完整审计完成。

原混合负载的有界测试已经结束：MongoDB 有 2/3 组联合合格，ES 有 1/3，尚不能称完成三次合格重复。MongoDB 随后在校准时发生转发连接中断；18 个完整试验可用，但失败校准的远端部分证据未导出，不能据此断言错误或 OOM 为零。ES 首次纯写 Weir 校准中容器退出，r034 缺少完整写账本与审计，123 个 UNKNOWN 的最终落库情况未确认，成功 API 写入不计为已审计 APPLIED。

两条纯写路径分别采用唯一一个新 fixture，与原混合 cohort 分开，不跨数据库 PID 拼接重复。MongoDB 纯写此前尚未开始，保留初始校准与最多两轮重新校准预算；ES 纯写使用原预算的 round1，只有 round2 可再替换完整配对。若新 fixture 再次中断就保留结果并收尾，不循环重建。MongoDB 新私有脚本在转发故障后先尝试保留 Pod 状态和原始数据，再清理；ES 在每次试验前检查 idle 客户端寿命，必要时仅在无活跃请求的边界重启该 owned 客户端。冻结 helper 的 idle 模式有 45 分钟上限，旧中断时间与之吻合，但缺少退出状态，不能将其当作已确认的事故根因。MongoDB 的容器入口为 busybox sleep21600，并非该 idle 模式。

“相同负载”在本报告中指相近的数据库实际进程 CPU。数据库 RSS、缓存、IO 和 GC 会随吞吐变化，配额相同不能证明这些量也相同；单个 CPU 运行点也不代表最大吞吐容量。收集请求可能增加低负载延迟，资源成本必须连同吞吐一起看。

采样边界有限精度：MongoDB 冻结采样器在读取本地 proc/cgroup 前记录采样开始时间，没有读取完成时间；ES 保存读取前后时间区间，正式要求区间完整落在测量窗口内、保守首末计数跨度至少 57 秒、两端空缺各不超过 2 秒。不挑选 10 秒窗口来匹配 CPU，不插值或用 CPU 比例折算吞吐。

证据与预先制定的方法保存在 [equal-load-v4](measurements/2026-10-02/equal-load-v4/plan.json)。生产源文件与二进制冻结来源为 [v4 manifest](measurements/2026-10-02/refinement-v4/build-manifest.json)；本轮不修改生产代码。

## 证据封闭与清理

四个独立 cohort 合计 115 个完整试验，其中 34 个正式试验构成 17 个实际配对（包括完整替换）。正式 warm+measure 合计 908765 个 APPLIED 写入完成内容审计；正式阶段 API/UNKNOWN 为零，ES 测量丢弃合计 3305，MongoDB 正式丢弃为零。预热、校准、未完成试验中的错误不合并成“正式零错误”的结论。

四份原始归档、逐成员 SHA256、独立原始核证和汇总复算保存在 [equal-load-v4](measurements/2026-10-02/equal-load-v4)。[终验](measurements/2026-10-02/equal-load-v4/final-verification.json)通过：1937 个原始成员与清单 SHA 一致，258 个冻结源文件、六份二进制及原二进制 bundle 未变，先前 871+31 个证据文件未变，四组分类复算无差异。终验通过表示证据与计算一致，不表示四个负载都完成三组合格重复。

两轮 MongoDB 的 owned namespace 已删除并独立确认 NotFound，精确转发进程退出、对应端口关闭；ES owned 容器、网络和数据卷已删除，foreign 资源保留。ES 默认 bridge ID 漂移单列，不能宣称整个 Docker inventory 字节一致。早期生成的 raw-member-manifest 中 archive_pending 是生成时的历史状态；最终归档状态以 sha256/index 与归档收据为准，保留历史 inventory 字节以维护来源哈希。
